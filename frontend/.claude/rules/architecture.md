# Architecture

- **State**: Angular signals everywhere for UI/session state (`signal`/`computed`/`effect`); no NgRx. The one Observable use is one-shot HttpClient calls in services, consumed in components via `.pipe(take(1)).subscribe({...})` — never long-lived subscription state.
- **Auth chain** (wired in `app.config.ts` via `provideHttpClient(withFetch(), withInterceptors([authInterceptor]))` + `provideAppInitializer(() => inject(AuthService).restoreSession())`):
  - `service/auth.service.ts` is the single auth facade: `token`/`claims`/`sessionActive` signals, `email`/`role` computeds, `isAdmin()` method. The 15-minute access JWT lives **only in memory** — nothing but `asset-manager.avatar` touches localStorage (legacy `asset-manager.token`/`asset-manager.refreshToken` keys are purged once in the constructor); the opaque refresh token is an **HttpOnly cookie** (`asset-manager.refreshToken`, `SameSite=Strict`, `Path=/auth`) that JS can neither read nor detect. `sessionActive` (an in-memory flag set on login/signup/refresh, cleared on logout/expiry) replaces the old cookie-presence check; `isAuthenticated()` is optimistic — live access token OR sessionActive — and still a method, not a computed (`Date.now()` isn't reactive); `hasLiveAccessToken()` holds the strict check. `refreshSession()` posts an **empty body** to `POST /auth/refresh` (the cookie is the credential; single-flight — rotation deletes the old token server-side, so a second concurrent call would 401 the session; single-flight is per-tab only: two tabs can race a rotation). `restoreSession()` is the startup hydration: called by the app initializer, it fires one blind cookie-refresh before bootstrap (the only way to learn whether a session exists); 401 → silent guest, **never** the login modal; a no-op on the server. `applyAuthenticationResponse()` is the public session installer (login/signup/refresh taps and spec seeding). `logout()` posts an empty body — refreshing first when the access token is expired, since `/auth/logout` is JWT-protected — and always clears locally (the cookie is cleared server-side; the revoke-all-tokens fallback died with the request body). `sessionExpired()` (refresh failed mid-session) clears the session and opens the login modal, matching guard denial. The `avatarUrl` signal has no backend source yet — seeded via `setAvatarUrl()`, deliberately not cleared on logout; the header falls back to initials derived from the JWT `sub`.
  - `interceptor/auth.interceptor.ts`: clones `withCredentials: true` onto every `/auth/*` request **before the refresh bypass** so the HttpOnly cookie flows both ways (the service also sets it on its own calls — belt and braces; non-auth URLs stay Bearer-only, which `Path=/auth` enforces anyway). Attaches `Authorization: Bearer` only for a live access token; when the access token is expired but `sessionActive` it **proactively** refreshes (single-flight) and sends with the new token; on any 401 for a non-`/auth` URL it retries once via one refresh (reactive safety net for clock skew and revoked-mid-flight tokens). `POST /auth/refresh` itself bypasses the interceptor's auth logic entirely — wrapping it would recurse and burn rotation. Refresh failure → `sessionExpired()`. Expired tokens are never sent: the backend 401s bad Bearer headers even on public endpoints. CSRF posture: `SameSite=Strict` + `Path=/auth` (refresh is the only purely-cookie endpoint; logout/change-password also require the Bearer header).
  - JWTs are decoded client-side without signature verification in `util/jwt-util.ts` (`decodeJwt`/`isExpired`); expiry is enforced by not sending expired tokens (plus the proactive refresh above). Claims include `typ: 'access'` (optional in `JwtClaims` so legacy tokens still decode).
- **Routing**: `app.routes.ts` is still empty; everything renders in `App`'s template (`app.html`: header, `router-outlet`, login + signup + change-password modals). Asset-section page components (`component/dashboard/`, `savings-passbooks/`, `land-assets/`, `cash-assets/`, `other-assets/`, `currencies/`) and `component/shared/sidebar/` exist only as empty CLI stubs — nothing routes or mounts them yet. `component/shared/menu-items.ts` sketches the intended role-gated nav but is dead code with landmines: a stray `import { type } from 'os'` (breaks the browser bundle if ever imported into the app) and `@Injectable()` without `providedIn`/provider — clean it up before wiring it anywhere. Guards exist and are ready: `guard/route-guard.service.ts` exposes `authGuard` (roles via `route.data.roles`) and `adminGuard`. Denial opens the login modal instead of redirecting — there is no `/login` route. `app.routes.server.ts` prerenders the root.
- **Modal pattern**: `service/modal.service.ts` holds visibility signals. Modals in `src/app/component/modal-form/` are mounted permanently in `app.html` and open themselves via `effect()` when the service signal flips — flow is header → ModalService → modal component, never component-to-component. Currently `login`/`signup`/`change-password` are wired; `confirmation` and `forgot-password` components exist as empty stubs (no logic, not mounted, not in ModalService).
- **Header** (`component/shared/header/`): avatar dropdown (change password, logout) driven by `AuthService.email`/`avatarUrl`, with an initials fallback when no URL is stored or the `<img>` errors (retry on avatar change via `effect`); mobile hamburger menu; outside-click and Escape close the dropdown via `HostListener`.
- **Directive**: `directive/auto-hide-scrollbar.ts` (`appAutoHideScrollbar`) adds `.is-scrolling` to the host while it scrolls and removes it 500 ms after; the thumb styling lives in `src/scss/modal.scss`. Applied to every mounted modal's `.modal-container`.
- **Service layer**: one service per backend resource in `service/` (`AuthService`, `UserService`, `CurrencyService`, plus one per asset type), all `providedIn: 'root'` with `inject(HttpClient)` and a `readonly baseUrl = \`${environment.apiUrl}/...\``. Request/response types live in `model/`.
- **Error display**: `util/api-util.ts` `getApiErrorMessage(error, fallback)` normalizes the backend's three error body shapes into a string for signal-backed `errorMessage` fields.
- **Forms**: template-driven (`FormsModule`/`NgForm`), not reactive. Field validation lives in `util/auth-util.ts` (email regex, password policy).
