# Architecture

- **State**: Angular signals everywhere for UI/session state (`signal`/`computed`/`effect`); no NgRx. The one Observable use is one-shot HttpClient calls in services, consumed in components via `.pipe(take(1)).subscribe({...})` — never long-lived subscription state.
- **Auth chain** (all wired in `app.config.ts` via `provideHttpClient(withFetch(), withInterceptors([authInterceptor]))`):
  - `service/auth.service.ts` is the single auth facade: `token`/`claims` signals, `email`/`role` computeds, `isAdmin()` method. `isAuthenticated()` is a method, not a computed — `Date.now()` isn't reactive. Session persists to `localStorage['asset-manager.token']`, guarded by `isPlatformBrowser` (SSR never touches localStorage). The `avatarUrl` signal persists to `localStorage['asset-manager.avatar']` — no backend source yet, seeded via `setAvatarUrl()` and deliberately not cleared on logout; the header falls back to initials derived from the JWT `sub`.
  - `interceptor/auth.interceptor.ts` attaches `Authorization: Bearer` only when a live, unexpired token exists — a stale header would 500 the backend's JWT filter even on public endpoints.
  - JWTs are decoded client-side without signature verification in `util/jwt-util.ts` (`decodeJwt`/`isExpired`); expiry is enforced by not sending expired tokens.
- **Routing**: `app.routes.ts` is still empty; everything renders in `App`'s template (`app.html`: header, `router-outlet`, login + signup + change-password modals). Asset-section page components (`component/dashboard/`, `savings-passbooks/`, `land-assets/`, `cash-assets/`, `other-assets/`, `currencies/`) and `component/shared/sidebar/` exist only as empty CLI stubs — nothing routes or mounts them yet. `component/shared/menu-items.ts` sketches the intended role-gated nav but is dead code with landmines: a stray `import { type } from 'os'` (breaks the browser bundle if ever imported into the app) and `@Injectable()` without `providedIn`/provider — clean it up before wiring it anywhere. Guards exist and are ready: `guard/route-guard.service.ts` exposes `authGuard` (roles via `route.data.roles`) and `adminGuard`. Denial opens the login modal instead of redirecting — there is no `/login` route. `app.routes.server.ts` prerenders the root.
- **Modal pattern**: `service/modal.service.ts` holds visibility signals. Modals in `src/app/component/modal-form/` are mounted permanently in `app.html` and open themselves via `effect()` when the service signal flips — flow is header → ModalService → modal component, never component-to-component. Currently `login`/`signup`/`change-password` are wired; `confirmation` and `forgot-password` components exist as empty stubs (no logic, not mounted, not in ModalService).
- **Header** (`component/shared/header/`): avatar dropdown (change password, logout) driven by `AuthService.email`/`avatarUrl`, with an initials fallback when no URL is stored or the `<img>` errors (retry on avatar change via `effect`); mobile hamburger menu; outside-click and Escape close the dropdown via `HostListener`.
- **Directive**: `directive/auto-hide-scrollbar.ts` (`appAutoHideScrollbar`) adds `.is-scrolling` to the host while it scrolls and removes it 500 ms after; the thumb styling lives in `src/scss/modal.scss`. Applied to every mounted modal's `.modal-container`.
- **Service layer**: one service per backend resource in `service/` (`AuthService`, `UserService`, `CurrencyService`, plus one per asset type), all `providedIn: 'root'` with `inject(HttpClient)` and a `readonly baseUrl = \`${environment.apiUrl}/...\``. Request/response types live in `model/`.
- **Error display**: `util/api-util.ts` `getApiErrorMessage(error, fallback)` normalizes the backend's three error body shapes into a string for signal-backed `errorMessage` fields.
- **Forms**: template-driven (`FormsModule`/`NgForm`), not reactive. Field validation lives in `util/auth-util.ts` (email regex, password policy).
